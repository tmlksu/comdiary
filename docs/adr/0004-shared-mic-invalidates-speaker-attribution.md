# ADR 0004: 共通マイクを検知したら話者帰属を落とす

- 状態: 採用
- 日付: 2026-08-13

## 背景

温度感(誰が何にどう反応したか)を記録したい。これは資料作成時に
「相手の関心に先回りする」ために効く。

しかし会議室に**共通マイクが 1 台**という構成では、文字起こしの話者ラベルが
1 人(または「会議室A」のような機器名)に寄る。この状態で LLM に話者を
推定させると、**発言していない人に感情や主張が紐づく**。

## 決定

話者比率を **Python が決定論的に計算**し、それを根拠に LLM の話者帰属を打ち消す。

- 単一話者が全発言の 70% 以上 → `mic_mode: shared` / `attribution: uncertain`
- 話者ラベルが 1 種類だけ → 同上
- ラベル付き行が全体の 50% 未満 → `attribution: uncertain`
- ラベルが 1 つも読めない → `mic_mode: unknown`、話者帰属は行わない

`attribution: uncertain` のとき:

1. プロンプトで LLM に「speaker / owner / raised_by は原則 null に」と指示する
2. それでも埋めてきた場合、`apply_mic_policy` が **後段で機械的に剥がす**
   (話者名は `evidence` に「(話者推定は不確実: X)」として退避し、確信度を 0.5 以下に落とす)

つまりプロンプトと後処理の二重で防ぐ。プロンプトは守られないことがあるため。

## 理由

**「何が論点だったか」は残し、「誰が言ったか」は捨てる。**

間違った人物に「声を荒げた」を紐づけるのは、
話者不明で記録するより明確に悪い。前者は人の評価を歪めるが、後者は情報が減るだけ。
かつ、資料作成の用途では「その論点に強い抵抗があった」だけでも十分に使える。

## 帰結

- `comdiary concerns` の集計で、共通マイクの会議由来のものは `(話者不明)` に集約される
- 会議正本の frontmatter に `mic_mode` / `speaker_attribution` が入るので、
  後から「この期間は共通マイクだった」と分かる
- 判定閾値は `src/comdiary/transcript.py` の `SHARED_MIC_THRESHOLD`
