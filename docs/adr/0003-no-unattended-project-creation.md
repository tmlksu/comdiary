# ADR 0003: 案件の自動作成をしない

- 状態: 採用
- 日付: 2026-08-13

## 背景

セグメントを案件に振り分ける際、既存のどれにも当てはまらないものが出る。
LLM に新しい案件を作らせれば全自動になる。

## 決定

**無人実行中に案件を作らない。** 未割当セグメントは `_inbox/` に置き、
`comdiary triage` で人が確認して `comdiary assign` するか、
`comdiary project new` で案件を起こす。

## 理由

非対称なコストがある。

- 未割当を放置するコスト = `comdiary triage` を見て 1 コマンド
- 誤った案件を作るコスト = 台帳に半端な案件が増え、以降の振り分けがそれに吸われ、
  気づいた時には複数の会議メモが誤った案件にぶら下がっている。戻すのは手作業

さらに、案件 id は**一度決めたら変えられない**(ディレクトリ名とリンクの根拠になる)。
LLM が付けた場当たり的な id が永続化されるのは避けたい。

## 振り分けの優先順位

1. **別名の完全一致** (決定論) — 確信度 0.95
2. **キーワード 2 個以上の一致** (決定論) — 確信度 0.8
3. **LLM の推定**、ただし `match.min_confidence` (既定 0.6) 以上のときだけ
4. それ以外 → `_inbox/`

複数の案件の別名に同時に一致した場合、LLM の推定がそのどれかを指していれば
それを採り、そうでなければ人に投げる(合同レビューなど、実際に曖昧なケース)。

LLM が実在しない `project_id` を返した場合は無条件で破棄する。

## 帰結

- 振り分けを外したときの一番効く対処は `comdiary project alias <id> <語>` で語を足すこと
- `match.auto_create_projects` は設定として存在するが既定 false
