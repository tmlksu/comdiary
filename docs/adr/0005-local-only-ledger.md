# ADR 0005: 台帳はローカル専用、ツール repo は会社データを持たない

- 状態: 採用
- 日付: 2026-08-13

## 背景

台帳には会社の会議内容・人の発言・温度感が入る。
一方、ツール本体は公開リポジトリとして開発したい。

共有の organization リポジトリに台帳を置くと、意図した範囲を超えて閲覧される。

## 決定

**2 つのリポジトリに分ける。**

| | ツール (`comdiary`) | 台帳 (ledger) |
|---|---|---|
| 内容 | コードとドキュメント | 非公開の業務データ |
| git | GitHub (private → いずれ public) | **ローカルのみ。remote 禁止** |

強制手段を入れる:

- `comdiary` は台帳に remote が設定されていると **コミットを拒否する**
  (`ledger/git.py` の `ensure_no_remote`。`[git] forbid_remote = false` で解除可)
- `comdiary doctor` が remote の有無を点検項目として表示する
- ツール repo の `.gitignore` が `comdiary.toml` (実パスが入る) と
  `ledger/` `memos*/` を無視する
- テストの題材はすべて合成データ。実データを fixture に置かない

## 理由

台帳はローカルでも **git 管理する価値がある**。living docs は
「いつ何が変わったか」が本体だからだ。だから「git を使わない」ではなく
「git は使うが remote を持たせない」が正しい落とし所になる。

そして事故は「うっかり `git remote add` する」形で起きるので、
運用ルールではなくツールが拒否する形にした。

## 帰結

- 台帳のバックアップは remote ではなく、ディスク・外部媒体側で担保する必要がある
- チームで共有したくなったら、この ADR を見直す
  (その時は LLM バックエンドのデータ取り扱いも併せて再検討する)
